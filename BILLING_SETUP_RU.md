# Подписка PRO и ЮKassa — подключение

## Что уже реализовано

499 ₽ за календарный месяц, рядом зачёркнуто 999 ₽. Бесплатно доступны одна
подключённая группа, одно сообщение в день по московскому времени и один объект
каталога. Планер с напоминаниями — PRO. Платный тариф снимает эти ограничения
приложения; ограничения самого MAX сохраняются.

Покупатель выбирает карту или СБП. Галочка автопродления **изначально снята**.
Без неё покупается один месяц. При согласии приложение запрашивает сохранение
способа оплаты в ЮKassa. Автопродление включается только если ЮKassa вернула
сохранённый способ (`payment_method.saved=true`). Для рекуррентных платежей
магазину может требоваться отдельное включение возможностей в ЮKassa,
особенно для СБП. Если способ не сохранился, приложение сообщает о ручном продлении.

Подписка активируется после ответа API ЮKassa `succeeded` и `paid=true`,
с проверкой 499 RUB, владельца, заказа и тестового режима. Возврат браузера
со страницы оплаты сам по себе доступ не выдаёт. Webhook повторно запрашивает
платёж через API; присланный статус не считается подтверждением.

## 1. Перед обновлением

Сохраните резервную копию постоянного каталога `DATA_DIR`: SQLite-базу и фото.
После обновления схема дополняется автоматически, записи пользователей не
удаляются. Старые пользователи без оплаченной подписки получают бесплатный тариф;
ранее показывавшийся пробный период не даёт бесплатный PRO.

Уже сохранённые лишние группы, объекты и записи планера не удаляются после
окончания подписки. Новые операции ограничиваются тарифом. Для бесплатных рассылок
используется первая подключённая группа; ненужные группы можно отключить.
Ограничения проверяются и при сохранении, и перед отправкой worker.
Ожидающие рассылки занимают суточный лимит на дату отправки; отмена до отправки
освобождает его. Удаление уже отправленной записи не сбрасывает лимит.

## 2. Настройки Ботхоста

Обновите ветку `codex/working-max-miniapp-2026-10-22`. Запуск по-прежнему:

```sh
python run.py
```

Добавьте переменные окружения. Ключи вводите в защищённых настройках Ботхоста,
не в GitHub, HTML или сообщениях чата.

| Имя | Что указать |
| --- | --- |
| `YOOKASSA_SHOP_ID` | shopId вашего магазина из ЮKassa. |
| `YOOKASSA_SECRET_KEY` | Секретный ключ API соответствующего магазина. |
| `YOOKASSA_RETURN_URL` | `https://bot-1792478387-3401-gogamisabi.bothost.tech/payment-return` |
| `YOOKASSA_RECEIPT_MODE` | `yookassa` для передачи состава чека в ЮKassa либо `external`, только если чеки действительно формирует ваша отдельная система. |
| `YOOKASSA_VAT_CODE` | При `yookassa`: код ставки НДС, подходящий вашему магазину. Его нужно уточнить по настройкам магазина/кассы. Значение автоматически не угадывается. |
| `YOOKASSA_TAX_SYSTEM_CODE` | Необязательно: код системы налогообложения из настроек кассы, если он требуется вашей интеграции. |
| `YOOKASSA_TEST_MODE` | `0` для реального магазина. `1` — только для отдельного тестового развёртывания с тестовым магазином. |

`MAX_BOT_TOKEN`, `FRONTEND_ORIGIN`, `DATA_DIR` и рабочую настройку
`MAX_API_BASE_URL=https://platform-api.max.ru` оставьте как раньше.
Для внешних платежей требуется исходящий HTTPS-доступ Ботхоста к `api.yookassa.ru`.
Все процессы должны использовать одну и ту же постоянную базу данных.

## 3. Как определиться с чеками

Поскольку вы ещё не знаете, как у вас подключены чеки, сначала уточните это
в поддержке ЮKassa или у специалиста, который подключал магазин. Можно отправить:

> Подключаю оплату ежемесячной подписки на сервис за 499 ₽ через API ЮKassa,
> картой и СБП, с сохранением способа оплаты для автопродления по согласию клиента.
> Подскажите, какой способ формирования чеков подключён к моему магазину,
> нужно ли передавать receipt при создании платежа и какие vat_code и
> tax_system_code использовать. Также прошу проверить доступность рекуррентных
> платежей картой и через СБП.

При `yookassa` приложение запрашивает email покупателя, передаёт одну услугу
«Непростопост PRO — 1 месяц» за 499 ₽ и включает чек в каждое автопродление.
При отсутствии настройки чеков оплата заблокирована с понятным сообщением.
`external` не подключает кассу автоматически и не формирует чек сам.

## 4. Уведомления ЮKassa

В настройках HTTP-уведомлений ЮKassa укажите:

```text
https://bot-1792478387-3401-gogamisabi.bothost.tech/api/billing/webhook
```

Включите события `payment.succeeded` и `payment.canceled`.
Это уведомления ЮKassa, они не меняют настройку webhook/polling бота MAX.
Кроме webhook, worker примерно раз в минуту проверяет незавершённые платежи.
После возврата в MAX покупатель может нажать «Проверить оплату» в профиле.

## 5. Как работает автопродление

- При первом согласии сохраняются дата согласия и версия текста согласия.
- По окончании оплаченного месяца создаётся платёж на 499 ₽ с сохранённым
  способом оплаты. Данные карты приложение не хранит.
- Неподтверждённый платёж не включает PRO. После успешного платежа начинается
  следующий календарный месяц. Ранняя ручная оплата добавляет месяц к оставшемуся сроку.
- Отмена продления находится в профиле. Уже оплаченный период остаётся активным.
  Уже отправленный в ЮKassa платёж может завершиться: отключение автопродления
  не является отменой или возвратом такого платежа.
- При явном отказе продление повторяется не чаще одного раза в сутки, максимум
  три попытки. Затем автопродление отключается, ошибка показывается в профиле.
- При сетевом сбое запрос повторяется с тем же сохранённым ключом идемпотентности;
  новый платёж для неизвестного результата не создаётся. После 23 часов
  неопределённого результата автоматические повторы прекращаются, нужна проверка
  платежа в кабинете магазина.
- Отмена пользователем не может быть отменена запоздавшим webhook старого платежа.

Возвраты выполняются через кабинет ЮKassa; автоматическая обработка возвратов
и пропорциональный перерасчёт подписки в этом обновлении не реализованы.

## 6. Планер и каталог

Для напоминаний сначала откройте личный чат с ботом MAX и нажмите «Начать».
В планере задайте контакт, время, напоминание в момент контакта/за 5, 15 или 60
минут и подготовленное сообщение. Бот пришлёт напоминание **владельцу планера**,
включая текст. Клиенту автоматически ничего не отправляется. Текст можно
скопировать из планера и отправить вручную.

Если PRO закончился, новые напоминания приостанавливаются. Будущие напоминания
могут продолжиться после оплаты; прошедшие автоматически задним числом не отправляются.
Старые записи, созданные до добавления напоминаний, остаются без автоматической
отправки — создайте новое касание для нового напоминания.

В форме рассылки выберите объект каталога. Название, адрес, цена и описание
попадут в редактируемый текст, фото добавятся к рассылке. При сохранении
делаются отдельные копии фотографий, поэтому удаление объекта не ломает
уже запланированное объявление.

## 7. Проверка перед приёмом реальных платежей

На отдельном тестовом развёртывании используйте тестовые реквизиты ЮKassa,
`YOOKASSA_TEST_MODE=1`, `YOOKASSA_RECEIPT_MODE=test` и отдельный `DATA_DIR`.
Режим `test` для чеков разрешён только с тестовым магазином и не заменяет чеки
при реальных платежах. В профиле будет явная пометка тестового режима.

Проверьте оплату без галочки, оплату с галочкой, активацию PRO, отключение
автопродления, повторную доставку webhook, напоминание себе и рассылку из каталога.
При переходе к реальным клиентам нужны реальные реквизиты, тестовый режим `0`
и настроенные реальные чеки. Тестовые платежи не должны смешиваться с рабочими данными.

Локальные тесты используют тестовые ответы API и не списывают деньги.
Реальные карточные/SBP-платежи, кассовые чеки и автопродление вашего магазина
пока не проверены: значения ключей и настройки кассы в облачной среде отсутствуют.
