# Лаеро + GitHub + Ботхост

## Что где находится

- **Лаеро:** один файл `frontend/index.html` из этого репозитория.
  В нём уже собраны HTML, CSS и JavaScript. Отдельно `static/app.js` на Лаеро не нужен.
- **GitHub:** весь репозиторий с сервером; Ботхост скачивает его сам.
- **Ботхост:** устанавливает Python-зависимости, запускает сервер и worker,
  хранит токен, базу и фото.
- **MAX:** в настройках Mini App указан адрес страницы **Лаеро**.

## 1. Обновите код на GitHub

Изменения находятся в ветке `codex/working-max-miniapp-2026-10-22`.
Если Ботхост позволяет выбрать ветку, выберите её. Если он использует только `main`,
сначала перенесите изменения в `main` через GitHub Pull Request и Merge.
Не загружайте ZIP-файл в репозиторий как отдельный файл: серверу нужны распакованные
`app.py`, `run.py`, `worker.py`, `max_events.py`, `billing.py`, `reminders.py`, `requirements.txt` и папки проекта в корне репозитория.

## 2. Подключите Ботхост

В настройках вашего проекта выберите GitHub-репозиторий
`giorgim7-glitch/neprostopost-bot` и ветку с обновлённым кодом.
Точное название полей зависит от панели Ботхост.

Установка зависимостей:

```sh
pip install -r requirements.txt
```

Команда запуска:

```sh
python run.py
```

Этот вариант запускает **оба** процесса: Gunicorn и worker.
Дополнительный второй worker запускать не нужно. При завершении одного из процессов
launcher завершает второй, чтобы хостинг мог перезапустить приложение целиком.
`Procfile` остаётся альтернативой для платформ, которые отдельно управляют web и worker.
Для отдельного фронтенда не нужен Node.js на Ботхост.

Если Ботхост предлагает только выбор стартового Python-файла, укажите `run.py`.
Если он не позволяет ни выбрать файл, ни задать команду запуска,
нужна проверка его доступных настроек; не предполагается, что он автоматически
поддерживает Procfile или несколько процессов.

Добавьте в переменные среды на Ботхост:

| Имя | Значение |
| --- | --- |
| `MAX_BOT_TOKEN` | Токен вашего бота, в защищённом поле. Не в HTML, GitHub или чате. |
| `FRONTEND_ORIGIN` | Origin Лаеро: `https://ваш-домен` без пути и завершающего `/`. Если страница `https://example.ru/app`, здесь `https://example.ru`. |
| `DATA_DIR` | Путь к постоянному каталогу данных, подключённому на хостинге. Узнайте доступный путь в настройках хранения Ботхост. |

Не выбирайте произвольный `/app/data`, если хостинг не выделил этот каталог как
постоянный диск. Без постоянного диска БД и фотографии могут исчезнуть при обновлении.
Порт берётся из `PORT`; без него используется 3000. Внешний адрес должен быть HTTPS.

Запустите/переразвёрните проект. Откройте его адрес с окончанием `/api/health`.
Ожидается JSON с `"status":"ok"` и `"max_configured":true`.
Последнее означает наличие токена, а не успешную проверку токена в MAX.

## 3. Подготовьте файл для Лаеро

Скачайте файл `frontend/index.html` (не `static/index.html`).
В начале файла есть строка:

```html
<meta name="neprostopost-api" content="https://bot-1792478387-3401-gogamisabi.bothost.tech">
```

Это адрес из исходного HTML, присланного пользователем. Он не был проверен на
доступность и принадлежность текущему проекту. Если Ботхост показывает другой
адрес, замените только значение `content` на действующий HTTPS-адрес Ботхост,
без `/api`, без пути и без завершающего слеша.

Загрузите/замените главную HTML-страницу вашего сайта на Лаеро этим файлом
и опубликуйте сайт. Конкретное поле загрузки или редактор зависит от Лаеро:
интерфейс должен позволять исполнять JavaScript и загружать MAX SDK с `st.max.ru`.
Если используется iframe, на Ботхост в `FRONTEND_ORIGIN` нужен origin самого
документа с приложением, а не внешней страницы-обёртки.

Если будете менять исходный `static/app.js`, пересоберите файл командой:

```sh
python build_frontend.py --api-origin https://ваш-бэкенд.bothost.tech
```

В этой облачной среде такая команда уже выполнена для адреса из старого фронтенда.

## 4. Подключите MAX и проверьте

1. В настройках Mini App вашего бота укажите опубликованный HTTPS-адрес **Лаеро**.
2. Откройте приложение из MAX. В обычном браузере оно просит войти через MAX — это ожидаемо.
3. Добавьте клиента и объект с фотографией. Обновите вкладку и проверьте сохранённые данные.
4. Для рассылок добавьте бота администратором тестовой группы, убедитесь, что ваш
   аккаунт тоже администратор. Отправьте в нужную группу `/connect`, подождите
   10 секунд, затем вернитесь в Mini App. Нажмите «Найти мои группы в MAX» и «Подключить»
   возле нужной группы. Ручной ввод ID оставлен как запасной способ.
5. Запланируйте одну тестовую рассылку на ближайшие несколько минут. Проверьте
   статус «Отправлено» и само сообщение в группе.

## Если не работает

- **503 / MAX_BOT_TOKEN:** токен не добавлен или приложение не перезапущено.
- **401:** откройте Mini App заново из MAX; проверьте, что токен принадлежит этому боту.
- **Ошибка сети / CORS:** сравните адрес Ботхост в HTML и origin Лаеро в `FRONTEND_ORIGIN`.
- **Поиск не видит группу:** после обновления отправьте `/connect` в саму группу,
  подождите 10 секунд и повторите поиск. Получение событий требует работающего
  worker. Если показана ошибка polling/webhook, пришлите её текст без токенов.
- **Рассылка остаётся запланированной:** проверьте в логах запуск worker и команду `python run.py`.
- **После обновления исчезли данные:** проверьте подключение постоянного диска и `DATA_DIR`.

Подписка PRO, платежи и напоминания добавлены. Для приёма платежей
нужно выполнить [настройку ЮKassa](BILLING_SETUP_RU.md). Реальная доставка и вход
в MAX требуют проверки с вашим токеном; локальные тесты используют тестовые ответы MAX.
