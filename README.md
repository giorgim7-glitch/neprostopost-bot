# Непростопост

Flask API и Mini App MAX на одном адресе. Главная страница `/` раздаёт
`static/index.html`, запросы интерфейса идут на `/api/*` того же сервера.
Отдельный хостинг HTML и настройка CORS для обычного запуска не нужны.

## Запуск

Нужны Python 3.12 и HTTPS-хостинг для Mini App. Node.js 22.22.2+, 24.15+ или 26+ нужен только
для тестов интерфейса; сборки фронтенда нет.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
# Задайте MAX_BOT_TOKEN через защищённые переменные среды вашего хостинга.
# Не добавляйте токен в HTML, Git или сообщения чата.
.venv/bin/gunicorn --bind 0.0.0.0:3000 --workers 1 app:app
```

В другом процессе, с теми же переменными и путями:

```sh
.venv/bin/python worker.py
```

`Procfile` описывает оба процесса. Если хостинг запускает только `web`,
добавьте отдельный постоянно работающий `worker`. `Procfile.txt` сохранён
для совместимости, его содержимое совпадает с `Procfile`.

Переменные:

| Имя | Назначение |
| --- | --- |
| `MAX_BOT_TOKEN` | Настоящий токен бота: сервер проверяет HMAC входа и обращается к MAX API. Без него вход и worker недоступны. Прокси-подстановка только в HTTP не подходит для локального HMAC. |
| `DATA_DIR` | Постоянный каталог данных; по умолчанию `.data` рядом с `app.py`. |
| `DB_PATH` | SQLite-файл, по умолчанию `$DATA_DIR/data.db`. |
| `UPLOAD_FOLDER` | Каталог фото, по умолчанию `$DATA_DIR/uploads`. |
| `FRONTEND_ORIGIN` | Для отдельно размещённого фронтенда: допустимые CORS origins через запятую. Встроенный фронтенд использует один origin с API. |
| `PORT` | Порт при запуске `python app.py`; для Gunicorn задаётся `--bind` (в Procfile переменная учтена). |

Web и worker должны видеть **один и тот же SQLite-файл и каталог фото**.
Храните их на постоянном диске одного хоста. Не запускайте независимые копии
на разных файловых системах. Схема базы обновляется автоматически без удаления
существующих записей. Резервируйте базу и фото перед обновлением приложения.

Укажите публичный HTTPS-адрес приложения в настройках Mini App бота MAX.
Вход работает при открытии из MAX: `WebApp.initData` проверяется сервером,
сессия хранится в `sessionStorage` и передаётся как Bearer-токен. Снаружи MAX
показывается приглашение открыть приложение из бота; обхода входа нет.

## Группы, рассылки, каталог

1. Добавьте бота администратором группы MAX.
2. Откройте Mini App из бота, во вкладке «Рассылки» укажите числовой ID группы.
   Сервер проверяет, что текущий пользователь — администратор этой группы.
3. Задайте текст, необязательные фото, будущие дату и время на своём устройстве.
   Интерфейс передаёт UTC с часовым поясом; worker отправляет задание при наступлении срока.
4. Статус обновляется при открытии вкладки и каждые 15 секунд. При отключении группы ожидающие
   отправки отменяются; отправляющееся задание удалить нельзя.

Worker проверяет права повторно перед отправкой, загружает изображения через
MAX `/uploads?type=image` и отправляет `/messages?chat_id=...`. Контракт сверён
с официальным пакетом `@maxhub/max-bot-api` 1.0.2 (API v2 `platform-api2.max.ru`).
Работает только один worker на SQLite-файл. Повторяются явные временные отказы
и ошибки до отправки (до трёх попыток). При тайм-ауте POST, сбое 5xx или прерывании
worker результат помечается как неизвестный: проверьте сообщение в группе,
прежде чем создавать новую рассылку. Автоматический повтор в этом случае мог
бы создать дубликат.

Фото каталога доступны только владельцу по авторизованному запросу; интерфейс
загружает их с Bearer-заголовком. Данные из API выводятся с экранированием HTML.
Касания клиентов сохраняются в планере; push-уведомления и платёжный провайдер
не подключены. Статистика подписчиков не выдумывается: неизвестное значение — «—».

В настройках сети нужны `platform-api2.max.ru`, для клиентского SDK `st.max.ru`,
для шрифта `fonts.googleapis.com` и `fonts.gstatic.com`. Загрузка вложений также
требует доступа к HTTPS-хосту, который MAX вернёт в ответе `/uploads`.
Конкретный хост необходимо проверить с настоящим токеном; он не был установлен
по тестовым ответам.

## Проверки

```sh
.venv/bin/python -m unittest discover -s tests -v
npm ci
TEST_PYTHON="$PWD/.venv/bin/python" npm test
```

Серверные тесты используют временную БД и искусственный ключ. DOM-тест
исполняет реальный JS в jsdom и обращается к временному Flask-серверу по HTTP:
вход, создание/удаление клиента, даты, статистика, каталог с фото, поиск,
экранирование HTML, группы, расписание и истечение сессии.
Только внешние вызовы MAX заменены тестовыми ответами. Эти проверки
не подтверждают реальную авторизацию SDK и доставку сообщений в MAX.

Проверка развёртывания: `/` возвращает HTML, `/api/health` возвращает
`status: "ok"`, `/api/me` без Bearer возвращает 401. Для окончательной проверки
MAX нужны настоящий токен, настроенный URL Mini App, тестовая группа и оба
работающих процесса. Не публикуйте тестовые ключи из `tests/` как токен бота.
